# Архітектура AI-агента

## 1. Проблеми, які вирішує агент

Агент автоматизує створення мінімального кросплатформного проєкту Hello World
на Rust. Він допомагає уникнути ручного налаштування структури проєкту,
базової перевірки функціональності та CI для різних операційних систем.

У результаті проєкт має містити конфігурацію Cargo, бібліотечний код і тест
`BasicAddition`, локальні скрипти перевірки для Windows та Unix-подібних
систем, а також GitHub Actions для Windows, Linux і macOS.

## 2. Skills

- **`project-scaffold`** — створює базову структуру Rust-проєкту, зокрема
  `Cargo.toml`, `src/lib.rs` і каталог `tests/`.
- **`build-and-test`** — налаштовує локальні скрипти збірки й тестування
  (`ci.sh` і `ci.bat`) та перевіряє проєкт командами Cargo.
- **`github-actions`** — створює workflow GitHub Actions, який запускає
  перевірки проєкту на Windows, Linux і macOS.

## 3. Commands

- **`git-init`** — ініціалізує Git-репозиторій проєкту.
- **`create-project`** — створює Cargo-проєкт, його бібліотечний код і
  структуру для інтеграційних тестів.
- **`create-build`** — додає локальні скрипти збирання та тестування для
  підтримуваних платформ.
- **`create-actions`** — додає конфігурацію CI GitHub Actions для трьох
  операційних систем.
- **`check`** — виконує перевірки проєкту, зокрема збірку та тести Cargo.
- **`init`** — оркеструє повний початковий процес: запускає потрібні команди
  послідовно й завершується після перевірки результату.

## 4. Дані між етапами

Етапи передають далі створені файли та результати попередніх перевірок:

1. **`Cargo.toml`** визначає ім'я та метадані пакета, залежності й налаштування
   Cargo. Це вихідна конфігурація для компіляції та тестування.
2. **`src/lib.rs`** містить бібліотечний код Hello World і функціональність,
   яку перевіряє тест.
3. **`tests/`** містить інтеграційний тест `BasicAddition`, що використовує
   публічний інтерфейс бібліотеки та перевіряє очікуваний результат.
4. **`ci.sh` / `ci.bat`** запускають локальні команди Cargo для перевірки
   конфігурації, збірки й тестів. Скрипти враховують відмінності між Unix-
   подібними системами та Windows.
5. **`ci.yml`** описує workflow GitHub Actions. Він використовує ті самі
   Cargo-перевірки у середовищах Windows, Linux і macOS; для кожної платформи
   налаштовуються потрібні кроки виконання.

Таким чином, конфігурація Cargo визначає, що збирати, вихідний код надає
поведінку для тесту, а локальні скрипти й workflow CI відтворюють перевірку
вручну та в автоматизованому середовищі.

## 5. Обробка помилок в `init`

`init` виконує залежні етапи послідовно й перевіряє результат кожного з них.
Якщо команда завершується помилкою, оркестратор зупиняє процес, повідомляє,
який саме етап не вдався, і передає користувачу інформацію про причину.
Наступні етапи, яким потрібен невдалий результат, не запускаються. Це
запобігає ситуації, коли помилка створення проєкту приховується за подальшою
помилкою збірки чи тестування.

Якщо помилка виникає під час фінальної перевірки, `init` також повертає
невдалий результат, щоб проблему можна було виправити до використання
проєкту або його CI.
